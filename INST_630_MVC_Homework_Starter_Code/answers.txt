1. MVC separates an application into three components (model, view, and controller).
    This makes the code easier to organize, read, update, and test.

2. The rating rule belongs in the model because the model manages the logic for filtering.
    Keeping the rule out of the controller prevents user interaction logic mixing with
    filtering logic.

3. The view would change the most because it controls how the information is displayed on
    the webpage. The model and controller would remain mostly unchanged because the  data
    and button interactions would work the same.

4. MVC does not require three separate JavaScript files, but it's easier to read and maintain
    them in three separate files.

5. The model should manage the data from a REST API because it handles retrieving, storing,
    and providing data to the controller, and then the view.
